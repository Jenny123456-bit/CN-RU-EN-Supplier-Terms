OPEN API · 外部接入

把术语库接进你自己的工具。

三种接法：静态 JSON 端点（零后端、走 CDN）、JS SDK（一行嵌入检索面板）、iframe 嵌入（整站挂到内网）。

1 · 静态 JSON 端点

部署在 GitHub Pages 后即可直接 GET，带 CDN 缓存，适合脚本、表格、内部系统拉取。

/api/terms.json
/api/index.json
/api/search-index.json

2 · JS SDK

引入一个文件，得到 ZRTerms.search() 与可挂载的检索面板。

<script src="sdk/zhru-terms.js"></script>
<script>
  ZRTerms.search("换装").then(list => console.table(list));
  ZRTerms.mount("#my-box", { query: "слот" });
</script>

ABOUT · 项目说明

一个词，一列车，一笔钱。

这个工具出发点很小：关务协调岗每天要为「一个词」赔钱，那就先把这件事练一遍。

为什么做这个

中俄线单证的痛不在翻译水平，而在口径。同一个动作，中方说换装、俄方写 перегрузка、英文合同写 transshipment；同一个费，合同写 demurrage、俄铁只认 простой。译法一旦分叉，报关单与运单就对不上，退单、重报、滞期，一条链全被拖住。

所以这里不追求「大而全的词典」，而是把会直接造成退单的 139 个词先钉死：一条推荐译法、若干变体译法、一句易错提示、一个场景例句。

术语口径

  • 推荐译法取俄方单证与法规文本的惯用写法，不取直译。
  • 变体译法保留行业口语与旧称，用于识别"同一术语多种译法"。
  • 高风险标记指混淆后直接导致退单、滞期或税费争议的词。
  • 例句为场景化示例，不引用真实单证数据。

技术形态

  • 纯静态 · 零构建 · 零后端，双击 index.html 即用。
  • AI 助手接任意 OpenAI 兼容接口（DeepSeek / 通义 / OpenAI / 本地 Ollama），密钥只存本地。
  • 无密钥时自动降级为「离线检索脑」，仍可回答术语对比类问题。
  • 单证校验全程本地正则匹配，文本不上传。
